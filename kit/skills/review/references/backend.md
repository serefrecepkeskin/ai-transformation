# Backend lens (APIs, services, ORM, jobs, migrations)

Order of importance. Each item names the failure it catches. The repo's `AGENTS.md` names its concrete helpers
(the scoping predicate, the permission dependency, the rate limiter) — read it first.

1. **Scoped to the caller.** Any query reaching a row by id carries the caller's scope (tenant / organisation /
   owner) *inside the WHERE*, sourced from the session — never from body/query/path. Post-hoc checks and "check
   after the write" are findings. Related ids taken from the request body are validated the same way. Scoped-out
   rows are 404, never 403.
2. **List and count agree.** A list and its count share one predicate list; a `scope` parameter on a repository
   method is passed, not defaulted.
3. **Permission declared.** A new or changed route declares the repo's auth/permission gate (or an explicit,
   justified exemption); payload-dependent transitions (status changes) are enforced in the service, not the route.
4. **Layering.** Route thin → service orchestrates → repository owns queries. DB access in a route, a commit inside
   a repository when the service owns the transaction, a raw HTTP error for a domain outcome, reading env vars
   instead of the settings layer — all findings.
5. **Async correctness.** Missing `await`, blocking calls on the event loop, a session shared across tasks,
   background jobs assuming request context.
6. **Cost-bearing endpoints** (LLM, SMS/e-mail, uploads, bulk work) have an explicit rate limit.
7. **Contracts.** Response models match what the service returns; enum-like values keep their documented
   vocabulary; error strings a client matches on are unchanged.
8. **Migrations.** One per change, generated by the tool, reviewed by hand (renames, indexes, constraints, server
   defaults for NOT NULL additions), real downgrade, data steps separate; deploy order stated; every other reader
   of the table (the workspace guide's Shared data) updated or named.
9. **Tests.** New endpoint/service/job → test exists, exercises the edge cases, mocks external I/O. A changed
   behaviour without a changed test is a finding. Guard tests (auth enforced, permission declared) still pass.
10. **Cross-repo effects.** Anything written by one repo and read by another keeps both sides' assumptions; twin
    implementations of the same rule stay identical.
